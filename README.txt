АВИАМОДЕЛЬНЫЙ КЛУБ ВОЛГОДОНСКА — сайт клуба
============================

ЧТО ЭТО
  Сайт авиамодельного клуба: новости, расписание, команда,
  профили с наградами, личный кабинет, парк моделей.
  Ставится на телефон как приложение (PWA) и работает офлайн.

  Название «Авиамодельный Клуб Волгодонска» — временное, меняется в двух местах
  (см. «Как поменять название»).


ЗАПУСК
  python app.py
      -> http://localhost:5000

  База aero.db создаётся автоматически при первом старте.
  Всё хранится в этом одном файле — он же и есть резервная копия.

  Нужен Python 3.9+ и Flask. Если Flask нет:
      pip install flask


ПЕРВЫЙ ВХОД
  1. Откройте /register, заведите себе аккаунт
  2. Заявка попадёт в раздел «Админ» (нужен доступ к базе при первом
     разе — сайт ещё не знает, кто тут админ)

     Проще всего так: зарегистрируйтесь, затем в консоли выполните

       python make_admin.py ваш@email.ru

     Скрипт выдаст этому аккаунту все четыре роли и одобрит его.
     Дальше роли раздаются уже из веб-интерфейса.

  3. Войдите — появится «Админ» и «Редактор» в меню.


РАЗДЕЛЬНЫЕ АККАУНТЫ: ЛИЧНЫЙ И АДМИНСКИЙ
  Один человек может держать два аккаунта: обычный — для себя как
  спортсмена и тренера, второй — только для управления клубом.
  Так повседневная работа не смешивается с админскими правами.

  Порядок действий:
    1. Выйдите из своего аккаунта
    2. Зарегистрируйте второй: /register
       Например почта admin@вашдомен.ru, имя «Администратор клуба»
    3. Войдите в ПЕРВЫЙ (нынешний) аккаунт
    4. «Админ» -> у второго аккаунта поставьте галочку
       «Администратор» -> Сохранить
    5. В том же разделе снимите галочку «Администратор» у себя
       -> Сохранить
    6. Войдите вторым аккаунтом

  Или одной командой из консоли:
    python make_admin.py admin@вашдомен.ru          выдать все роли
    python make_admin.py --demote вы@вашдомен.ru    снять с себя

  ЗАЩИТА: снять роль администратора с последнего админа нельзя —
  ни через сайт, ни скриптом. Иначе управлять клубом будет некому.
  В панели «Люди» сверху видно, сколько сейчас администраторов.

  Совет: админскому аккаунту достаточно роли «Администратор».
  Роли «Спортсмен» и «Тренер» ему не нужны — они у личного.


РОЛИ
  У одного человека может быть сразу несколько ролей — они
  складываются, а не заменяют друг друга.

    admin    Администратор — люди, роли, расписание, награды
    editor   Редактор      — новости
    coach    Тренер        — расписание, награды, парк учеников
    athlete  Спортсмен     — свой профиль и свои модели

  Выдаются в «Админ» -> галочки у каждого пользователя.


ЧТО ГДЕ ЛЕЖИТ
  app.py                  весь сервер
  uploads/                загруженные фотографии (создаётся сама)
  templates/*.html        страницы
  static/style.css        оформление
  static/sw.js            офлайн-режим
  static/manifest.webmanifest   описание приложения
  aero.db                 база (создаётся сама)


НАЗВАНИЕ КЛУБА
  Правится в «Админ» -> «О клубе» -> блок «Название клуба».
  Три поля:

    Полное название  — заголовок вкладки браузера, имя приложения
                       на телефоне, подпись в API
                       (по умолчанию: Авиамодельный Клуб Волгодонска)
    Коротко          — крупным в шапке слева вверху
    Город            — мелким под коротким названием

  Под полями видно, как будет выглядеть шапка.

  Если очистить поле и сохранить — вернётся значение по умолчанию.
  Без названия сайт не останется.

  ВАЖНО: если сайт уже установлен на телефон как приложение, его имя
  на домашнем экране сменится только после переустановки. Браузер
  запоминает название при установке. Поэтому название лучше
  определить до того, как позовёте людей ставить приложение.


СТРАНИЦА «О КЛУБЕ»
  Открывается по /about, пункт меню «О клубе».
  Правятся: описание клуба, «как к нам попасть», телефон, почта,
  где собираемся, адрес. Всё в «Админ» -> «О клубе».

  Пустые поля просто не показываются. Телефон и почта выводятся
  ссылками: с телефона можно позвонить или написать в один тап.
  Пока ничего не заполнено — стоит нейтральный текст-заглушка.


ПОВТОРЯЮЩЕЕСЯ РАСПИСАНИЕ
  Тренировку можно завести один раз на весь сезон.
  «Админ» -> «Расписание» -> блок «Добавить тренировку» -> поле «Повторять».

  Варианты:
    Не повторять       — одно занятие (по умолчанию)
    Каждую неделю      — тот же день и время
    Раз в две недели   — через неделю
    По дням недели     — отметить нужные дни (например вт, чт, сб)
    Каждый день        — для сборов и интенсива

  «До какой даты» — конец периода. При выборе даты начала сайт сам
  подставляет конец через 9 месяцев (примерная длина сезона),
  дату можно поправить.

  ВНИМАНИЕ: «До какой даты» ВКЛЮЧИТЕЛЬНО — последнее занятие будет
  в этот день, если он подходит по правилу.

  Время и длительность переносятся на все занятия серии:
  указали 15:00—17:00, значит каждое занятие будет таким.

  Как это выглядит:
    - в админке серия показана ОДНОЙ строкой с пометкой «серия · 12»
    - в расписании видны ближайшие 8 занятий, остальные под кнопкой
      «Показать ещё N занятий»

  Удаление:
    «Удалить»     — убрать одно занятие, остальная серия остаётся
    «Всю серию»   — убрать все занятия серии сразу (спросит подтверждение)

  Записи участников на конкретные даты при удалении серии тоже удаляются.

ПРАВКА ВСЕЙ СЕРИИ
  В списке тренировок у серии есть синяя пометка «серия · 12 →».
  Нажмите её — откроется страница правки серии.

  Что можно сделать сразу для всех занятий:

    1. Название, место, группа, тренер, лимит мест, заметка
       -> «Применить ко всей серии»
       Даты не меняются, записи участников сохраняются.

    2. Время — «Изменить время»
       Меняется только час, даты те же. Если не указать новое
       окончание, сохранится прежняя длительность.
       ЗАПИСИ НЕ ТЕРЯЮТСЯ: занятия сохраняют свои номера.

    3. Продлить серию
       Добавляет занятия по тому же правилу до указанной даты.
       Существующие записи не трогаются.

    4. Перенести серию — «Перенести серию»
       Указываете НОВУЮ дату первого занятия. Все занятия сдвинутся
       на столько же дней, сколько между старой и новой датой.
       Интервалы внутри серии сохраняются, записи остаются.
       Пример: тренировались по вторникам с 3 ноября, зал освободился
       только с 10 ноября — ставите 10 ноября, вся серия уезжает
       на неделю вперёд.

       Если серия была «по дням недели», после сдвига дни пересчитаются
       сами: вт/чт при сдвиге на день станут ср/пт.

    5. Перенести ОДНО занятие
       В таблице занятий внизу есть колонка «Перенести»: дата, время
       и стрелка. Меняет только это занятие, остальная серия не трогается.
       Удобно, когда одну тренировку сдвинули на другой день.

    6. Сократить серию
       Удаляет занятия ПОСЛЕ указанной даты — например, если сезон
       закончился раньше. Здесь записи на удалённые даты пропадут,
       поэтому сайт заранее пишет, сколько именно.
       Всю серию так удалить нельзя — для этого отдельная кнопка.

  Внизу страницы — таблица всех занятий серии с числом записавшихся.
  Любое можно убрать отдельно.

  Зачем это нужно: при удалении и пересоздании серии записи участников
  теряются. Правка сохраняет номера занятий, поэтому записи остаются
  на своих местах.


ЗАПИСЬ НА ТРЕНИРОВКИ
  Участник видит «Записаться» в расписании и в кабинете.
  На тренировке может быть лимит мест — поле «Мест» при создании.
  Если мест нет, кнопка меняется на «мест нет».

  Кто видит список записавшихся:
    админ и тренер — в «Админ» -> «Расписание» -> число в колонке
                     «Записались»; по клику имя, время записи и
                     возможность снять человека

  Участник видит свои записи в кабинете, раздел «Я записан»,
  и может отменить прямо оттуда.

  Записаться дважды на одну тренировку нельзя — база не даст.
  Отмена и повторная запись работают свободно.


ПАРОЛИ
  Смена своего пароля: кабинет -> «Пароль и безопасность» (/security).
    Нужен текущий пароль и новый, не короче 8 символов.

  Забыли пароль — администратор выдаёт временный:
    «Админ» -> «Люди» -> кнопка «Новый пароль» у нужного человека
  Паpоль генерируется вида «винт-4821», его легко продиктовать
  по телефону. Старый сразу перестаёт работать.

  ВАЖНО: временный пароль показывается один раз, в жёлтой плашке
  сверху. Скопируйте его сразу — потом посмотреть негде, можно
  только выдать новый.

  Что не сделано: восстановление по почте. Для него нужен почтовый
  сервер и домен, поэтому пока только через администратора.


РЕЗЕРВНАЯ КОПИЯ
  «Админ» -> «Резервная копия» -> «Скачать aero.db»
  Отдаёт базу целиком, файл вида aero_2026-10-19_14-30.db

  Внимание, внутри хеши паролей — файл никому не пересылайте.
  Доступ есть только у администратора.

  Фотографии в базу не входят! Они лежат в папке uploads.
  Полная копия = aero.db + папка uploads.

  ЧЕГО НЕТ: автоматических копий по расписанию. Пока это кнопка,
  которую надо нажимать руками. Если нужны ежедневные — делается
  заданием в cron на сервере, скажите, добавлю.


ОБНОВЛЕНИЕ ВЕРСИИ
  Распакуйте архив поверх папки сайта с заменой и перезапустите.
  База подтягивается автоматически при старте: недостающие таблицы
  и колонки создаются сами, данные не трогаются.

  Поэтому больше не нужно удалять aero.db при обновлении.


АДМИНКА
  /admin          люди: заявки, роли
  /admin/events   расписание: добавить, переименовать, удалить
  /admin/awards   награды: добавить, удалить

  Тренер видит расписание и награды, но не раздел «Люди».


API ДЛЯ ПРИЛОЖЕНИЯ
  Всё отдаётся в JSON. Корень — /api/v1/ — там список методов.

  Публично, без входа:
    GET /api/v1/news              новости
    GET /api/v1/news/<slug>       одна новость целиком
    GET /api/v1/schedule          расписание (upcoming / past)
    GET /api/v1/team              участники
    GET /api/v1/people/<id>       профиль, награды

  Через токен:
    POST /api/v1/login            {"ident": "...", "password": "..."}
                                  -> {"token": "..."}
    GET  /api/v1/me               свой профиль
    GET  /api/v1/me/fleet         свои модели
    PATCH /api/v1/me/fleet/<id>   {"status": "fly"}

  Заголовок для защищённых методов:
    Authorization: Bearer <token>

  Токен живёт бессрочно, пока не удалить запись в таблице api_tokens.
  Пароль и телефон в API не отдаются никогда.


ФОТОГРАФИИ
  Новости — «Редактор» -> новость -> «Добавить фотографии».
    Можно выбрать сразу несколько. Первое фото становится обложкой
    в списке новостей. Остальные показываются галереей на странице.

  Профиль — «Кабинет» -> «Загрузить фото».
    Картинка обрезается по центру до квадрата 480x480.
    Админ может загрузить фото любому участнику:
    «Админ» -> таблица пользователей -> «фото» под аватаром.

  Что происходит с файлами:
    - всё пересохраняется в JPEG (даже PNG), лишний вес уходит
    - поворот с телефона учитывается (EXIF)
    - прозрачный фон становится белым
    - лежат в uploads/news и uploads/people
    - при удалении фото или новости файл стирается с диска

  Ограничения: до 8 МБ на файл, JPG/PNG/WebP/GIF.
  Нужна библиотека Pillow:
      pip install pillow

  Если Pillow не установлен, сайт работает, но фото не принимает.


ПАРК МОДЕЛЕЙ
  Кто видит чужие модели:
    владелец   — свои всегда
    тренер     — модели всех
    админ      — модели всех
    остальные  — не видят ничего

  Статусы: Летает / На ТО / В постройке / Списан.
  Классы вводятся текстом в свободной форме (F2D, F2B·З, F3A ...).

  Связи с ангаром для OBS сейчас нет: там свой файл fleet.json.
  Если нужно, чтобы сайт и ангар показывали одно и то же —
  это следующий шаг, делается через API.


ПРИЛОЖЕНИЕ (PWA)
  Открыть сайт на телефоне -> «Установить» в шапке
  (или «Добавить на главный экран» в меню браузера).

  Что работает офлайн:
    - ранее открытые страницы
    - последние ответы API
    - статика и иконки

  Что не работает офлайн:
    - вход и личный кабинет (нужна сеть)
    - отправка форм

  Push-уведомлений пока нет — это следующий этап, нужен HTTPS
  и серверный ключ. На localhost не заработают, только на домене.


КАК ПОМЕНЯТЬ НАЗВАНИЕ
  1. templates/base.html — блок <a class="logo">, строки «АЭРО» и «Волгодонск»
  2. static/manifest.webmanifest — поля name, short_name
  3. templates/index.html — заголовок на главной
  Перезапустить сервер.


ПЕРЕД ПУБЛИКАЦИЕЙ В ИНТЕРНЕТ
  Обязательно:
    1. Сменить SECRET_KEY. Сейчас стоит заглушка.
       Задайте переменную окружения AERO_SECRET или впишите свой ключ.
    2. Выключить debug в app.py (последняя строка, debug=True).
    3. Поставить нормальный сервер вместо встроенного Flask:
         pip install gunicorn
         gunicorn -w 2 -b 127.0.0.1:8000 app:app
       и проксировать через nginx.
    4. HTTPS. Без него PWA не установится, а пароли пойдут открытым
       текстом. Проще всего — Let's Encrypt через certbot.
    5. Хостинг в России: персональные данные граждан РФ
       по 152-ФЗ должны храниться на территории РФ.
    6. Бэкап по расписанию: и aero.db, и папку uploads/.
       База без фотографий восстановится с пустыми картинками.


ОГРАНИЧЕНИЯ ТЕКУЩЕЙ ВЕРСИИ
  - Восстановления пароля нет. Забыл — админ меняет вручную.
  - Фото новости нельзя переставить местами (обложка = первое загруженное).
  - Ангар для OBS и сайт пока не связаны.
  - Push-уведомлений нет.
  - Один язык — русский.
